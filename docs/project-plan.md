# A 股本地量化纸盘系统总计划

最后更新：2026-09-15

## 1. 项目目标

建立一个本地运行的 A 股量化研究、历史回测、实时纸盘模拟和人工决策辅助系统。

核心目标不是直接自动交易，而是验证一套完整、可审计、可恢复的量化研究与纸盘流程：

```text
真实行情接口
  → 数据标准化与质量检查
  → 因子计算
  → 本地模型评分
  → 组合构建与风控
  → 订单计划
  → PaperBroker 模拟撮合
  → 看板、通知和收盘报告
```

## 2. 已确认的硬边界

- 起始资金：100 万元。
- 股票范围：普通 A 股、创业板 300/301、科创板 688。
- 研究日线股票池：默认全量合格 A 股；盘中候选池：约 500 只。
- 第一阶段目标持仓：20–30 只。
- 研究频率：日频选股。
- 盘中模拟：优先使用 1 分钟行情。
- 真实交易：系统永远不连接券商发送真实委托。
- 自动模式：只允许自动模拟成交，不是真实下单。
- 人工模式：用户在网页确认后才进入纸盘撮合。
- 外部实际交易：只能由用户在券商软件中完成，再手工录入成交结果。
- 两融：只做账户、负债、借券费、维持担保比例和强平风险的模拟。
- 数据：股票价格和研究数据必须通过真实数据 API 获取，不能把手工 CSV 作为行情输入。
- 本地 Parquet：只作为真实 API 下载后的缓存，不作为数据来源。
- 大语言模型：第一阶段不作为交易模型核心依赖。

## 3. 当前运行方式

### 3.1 两个后台组成

- `quant-runner`：行情同步、因子计算、模型评分、风控、PaperBroker、报告。
- `quant-ui`：本地网页看板、人工确认、账户和报告查看。

UI 关闭不会影响 Runner；Runner 异常必须在诊断页和日志中显示。

### 3.2 统一启动入口

所有后续测试都必须先经过：

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\scripts\open_quantpaper.ps1 -Mode replay -FreshReplay -ForceRestart -NoBrowser
```

实时数据模式使用：

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\scripts\open_quantpaper.ps1 -Mode live
```

关闭后台：

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\scripts\close_quantpaper.ps1
```

打开流程负责：

- 复用已登录的东方财富经典客户端；
- 通过官方 `gmstarter.exe --token=<token>` 方式打开量化终端；
- 启动 FastAPI 和 Runner；
- 处理测试会话与后台计划任务的冲突；
- 为回放测试使用独立账本 `data/runtime/visual-paper.db`；
- 避免旧进程抢占 8000 端口；
- 计划任务在交易日 09:10–15:30 之外不启动东方财富和 QuantPaper；
- 后台 PowerShell、监督器和 Python 子进程均使用隐藏窗口，日志写入 `data/logs/`。

桌面快捷方式 `QuantPaper One-Click.lnk` 已指向实时模式启动入口。

## 4. 数据方案

### 4.1 接口抽象

策略不能直接依赖具体数据供应商，统一使用 `MarketDataProvider`：

- 交易日历；
- 股票列表、板块和行业；
- 日线行情；
- 1 分钟行情；
- 实时快照；
- 涨跌停价格；
- 停牌、ST、新股状态；
- 财务指标和公告日期；
- 融资融券标的和可借数量。

### 4.2 当前数据实现

- `ReplayProvider`：自动化测试和 UI 视觉验收专用，明确标记 `REPLAY`。
- `EastmoneyProvider`：当前默认实时和历史数据实现，使用东方财富掘金只读桥接；研究日线池与盘中实时池分离。
- `eastmoney_terminal_adapter.py`：只读终端适配器，支持后台快照轮询和量化终端 `init/on_bar` 60 秒行情回调；通过本地原子 feed 文件交给 `EastmoneyProvider`，不调用任何东方财富下单 API。
- 东方财富基础面接口：`stk_get_daily_mktvalue` 提供历史总市值/流通市值，`stk_get_daily_basic` 提供收盘价、总股本和换手率；行业分类使用单独的 `stk_get_symbol_industry`，必须记录分类的 `as_of` 日期。
- `TushareEodProvider`：保留为盘后历史数据备选，不作为实时行情源。
- `IfindProvider`：保留为可选实现，不作为当前默认方案。
- 没有可用实时源时必须标记 `UNAVAILABLE` 或 `STALE`，不能静默生成实时结果。

### 4.3 数据质量门禁

训练和回测前检查：

1. 交易日期、股票代码和 `(symbol, trade_date)` 唯一性；
2. OHLCV、成交额和复权方式；
3. 停牌、ST、新股、退市和涨跌停状态；
4. 行业、板块和股票池覆盖；
5. 财务公告日期必须早于或等于使用日期；
6. 标签未来区间完整；
7. 没有异常零值、负值和重复数据；
8. 数据更新时间和延迟在报告中可追溯。

当前补齐状态：代码和 SDK 均已具备市值接口，行业接口也已接入只读桥接，但小范围探针在量化终端关闭时返回“无法连接到终端服务”。因此暂不打开行业全量请求，也不覆盖现有 Parquet；必须在交易时段终端服务正常后先通过探针，再做新缓存同步。历史行业分类不能用当前分类倒填过去，必须按 `as_of` 日期做点时合并。

股票池分层：研究日线默认 `research_universe_limit = 0`（不在 Provider 层截断），盘中默认 `realtime_universe_limit = 500`；每日模型评分后，Runner 只把前 500 名候选和当前持仓加入实时行情列表。基础面接口仍先按 `fundamentals_universe_limit = 500` 分阶段同步，避免东方财富逐股票接口把全量历史任务拖成长时间阻塞。

任何关键检查失败，结果标记 `DEGRADED`，不生成看似正常的调仓结果。

## 5. 回测路线

20 个交易日纸盘是工程稳定性验收，不是研究因子有效性的前置条件。新的研究顺序是：

### B0：真实历史数据检查

通过实时数据接口获取至少 3 年日线、财务和交易日历，完成数据质量报告。不能使用手工 CSV。

### B1：因子基线回测

使用 M0 因子基线，按日 T 收盘生成信号，日 T+1 开盘成交，包含：

- 现金底线；
- 单票和行业权重上限；
- 最大换手和订单数量；
- T+1；
- 手续费、印花税和滑点；
- 涨跌停和板块交易规则。

### B2：LightGBM Walk-forward 回测

不能把全部历史数据训练一次后回看过去。必须按时间滚动：

```text
过去 2–3 年训练 → 后续 1 个月测试
向前滚动 1 个月 → 重新训练 → 再测试 1 个月
```

训练和验证之间至少留出 5 个交易日 gap，避免 5 日标签重叠造成泄漏。

### B3：历史回测后的纸盘

- 先做 5–10 个交易日工程验证；
- 重点检查数据中断、进程恢复、订单幂等、T+1、部分成交和报告；
- 稳定后再延长到 20 个交易日；
- 历史回测不能替代实时纸盘，因为历史数据无法完整覆盖实时延迟、盘口缺失、连接断线和人工确认延迟。

## 6. 因子计划

### F0：当前 11 个基线因子

- 动量：5、20、60、120 日收益率；
- 反转：5 日收益率取反；
- 波动：20 日实现波动率取反；
- 流动性：20 日平均换手率，缺失时使用成交额代理；
- 估值：PE、PB；
- 质量：ROE；
- 成长：利润增速或收入增速；
- 规模：总市值，缺失时使用成交额代理。

每个因子先横截面排名到 `[0, 1]`，再形成透明的 `factor_score`。缺失基本面数据使用中性分数，同时记录覆盖率，不能使用未来值填充。

### F1：价格与成交量扩展

加入 ATR、跳空、收盘位置、量价趋势、成交额稳定性、相对大盘 beta、行业相对动量、涨跌停距离。

### F2：基本面扩展

在公告日期可追溯后加入现金流质量、应计项、毛利率、资产负债率、净利率、盈利稳定性、经营现金流/净利润。

### F3：风险和暴露

增加行业、板块、市值、beta、波动和流动性暴露。部分风险因子只用于组合约束，不直接用于收益预测。

### F4：事件因子

最后考虑公告、回购、分红、解禁和业绩预告。没有可靠发布时间和历史回放能力的事件不进入纸盘信号。

每个新因子都要经过定义、覆盖检查、点时验证、单因子检验、去相关、成本后组合检验和 20 日影子运行。

## 7. 模型计划

### M0：透明因子基线

等权合成 11 个基线因子，作为所有机器学习模型的参照组。

### M1：本地 LightGBM

预测未来 5 个交易日的横截面超额收益。当前使用小模型，适合 RTX 5060 8GB：

- 160 棵树；
- learning rate 0.04；
- 24 个叶子；
- subsample 0.85；
- colsample 0.85；
- 固定随机种子；
- 保存完整 artifact、配置和数据版本。

### M2：模型比较

在同一数据、成本和交易规则下比较：

- LightGBM 回归；
- LightGBM 排序；
- Ridge/Elastic Net；
- 等权因子；
- 按历史 IC 加权因子。

模型不能直接生成绕过风控的订单，只能输出排名和建议仓位。

## 8. 训练与报告节奏

| 时间 | 工作 | 结果 |
| --- | --- | --- |
| 每个交易日收盘后 | 同步数据、计算因子、生成信号 | 因子快照、信号、数据质量 |
| 每周五收盘后 | 重新训练 LightGBM | 新模型候选和验证指标 |
| 每月第一个周末 | Walk-forward、因子归因和成本后评估 | 月度研究报告 |
| 每季度 | 复核因子定义、数据覆盖和规则 | 策略版本升级或回滚 |

训练失败时继续使用上一版通过门禁的模型，不使用半成品模型。

每个模型必须记录：

- 模型版本和哈希；
- 训练、验证、测试区间；
- 特征清单；
- 标签定义；
- 行数和数据快照；
- IC、Rank IC、RMSE、Top/Bottom spread；
- 成本后收益、回撤、换手和行业暴露。

## 9. 组合和交易约束

- 持仓数量：20–30 只；
- 单票上限：8%；
- 行业上限：25%；
- 现金底线：10%；
- 总敞口：默认不超过 100%；
- 最大日换手：15%；
- 每日最多 10 笔操作；
- 订单优先级：风险降低、融券回补、减仓、融资买入、普通新仓；
- 数据陈旧或不可用时暂停新增订单。

两融参数全部配置化。缺少利率、借券、维持担保比例或标的资格参数时，只允许观察和回放，不允许新增融资融券仓位。

## 10. PaperBroker 规则

- T+1；
- 主板、创业板、科创板交易单位；
- 涨跌停和一字板无法成交；
- 停牌无法成交；
- 买入按卖一加滑点，卖出按买一减滑点；
- 无盘口时使用下一根 1 分钟 K 线；
- 单分钟成交量参与率不超过 10%；
- 支持部分成交、撤单、有效期和人工确认延迟；
- 每笔订单记录决策时间、行情时间、确认时间、成交时间和价格来源。
