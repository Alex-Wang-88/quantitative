# 股票推荐系统 —— 独立方案设计

> 状态：**方案（未动工）** ｜ 日期：2026-09-18
> 定位：**与 `quantitative` 量化项目完全独立**的另一套系统。
> 量化项目继续做量化；推荐系统单独建仓、单独演进、两者不共享模型权重。

---

## 一、三个核心判断（先看结论）

### 判断 1：分开是对的，而且必须彻底分开

两个系统的**目标函数不同**：

| | 量化纸盘 | 推荐系统 |
| --- | --- | --- |
| 目标 | 验证一个**统计效应**是否稳健 | 给出**有说服力、可解释**的候选清单 |
| 成功判据 | 样本外超额、显著性 | 人看得懂、不遗漏关键风控、覆盖可控 |
| 对不确定性的态度 | 测不出就说测不出 | 必须给一个可操作的排序 |
| 自由度 | 越少越好（抗过拟合） | 可以多（表达力） |

把推荐塞进量化项目，会双向污染：量化的"显著性闸门"会让推荐永远输出"不确定"；
推荐的"多因子加权"会给量化引入一堆**不可证伪**的输入。

⇒ **推荐系统独立建仓**。唯一可以复用的是**归档层与存储模式**，**绝不共享模型**。

### 判断 2：「拿不到准确的消息数据」不是要解决的问题，是要**绕开**的问题

你问的这个问题，我的答案是：**别去解决它，绕开它。**

- 你**不需要预测消息**。你需要的是**测量市场对消息的反应**。
- 而"反应"本身就是**价格、成交量、资金流、涨停/开板**——这些是**客观、完整、可归档、可回测**的数据。
- 一条消息是真是假、影响多大，**不取决于文本，取决于它有没有换来真金白银**。假的第二天就死，真的会留下成交和资金痕迹。
- ⇒ **用"反应"做代理，完全绕开了"消息源可靠性"这个死结。**

### 判断 3：不能回测的数据，永远不能进权重

这是一条**可证伪性**限制，比"数据质量差"更根本：

- 新闻文本**没有历史时点快照**（财联社快讯接口已下线；东财新闻无按日回溯的"当时快照"）。
- 没有快照 ⇒ **永远无法回测** ⇒ 你**无法知道**它对推荐有没有用 ⇒ **它进权重就是纯噪声**，而且你永远不会发现。
- ⇒ 消息类数据**只能**做两件事：**(a) 风控闸门**、**(b) 人读的解释层**。**永不进打分权重。**

这条不是妥协，是本方案最重要的设计约束。

## 二、数据分层：可行性与处理策略（核心表）

按「是否可得 × 能否回测历史」分四层。**只有 T0/T1 能进权重，T2 只能前进不能回测，T3 不进权重。**

### T0 —— 已就绪，零新工作量 ✅

实测（2026-09-18 查本机归档）：

| 数据 | 实测现状 |
| --- | --- |
| 日线 OHLCV + 成交额 | `data/eastmoney_adjusted/daily.parquet`：**4,583,161 行 / 5,366 只 / 2023-01-03 → 2026-09-16** |
| **2024-09-24 基准价** | ✅ **在库内**（`last_le_924 = 2024-09-24`）⇒「924 以来涨幅」**直接可算** |
| 年内涨幅 | ✅ 同源可直接算（调仓 2,471,908 条 924 后记录） |
| 基本面日频 | `fundamentals_daily.parquet`（459 万行）→ 估值/质量/成长 |
| 上市日期 | `instrument_master.parquet` 已在库 → **次新股筛选可行** |
| 基准指数 | `benchmarks.parquet` → 相对强弱 |

⇒ **你列的"价格 / 924 以来涨幅 / 年内涨幅"三项，今天就能算，不需要任何新数据源。**

⚠️ 但注意：**`data/eastmoney_adjusted/industries/` 目录是空的** ⇒ 行业分类确实缺失（与量化项目的已知缺口一致）。

### T1 —— 可回补历史，实测确认 ✅

**这是本轮最有价值的发现。**

| 数据 | 实测结果 | 支撑的诉求 |
| --- | --- | --- |
| **同花顺题材归因** | ✅ **支持按历史日期回补**：<br>2026-09-18 → 79 条<br>2026-09-17 → 49 条<br>2026-05-09 → 79 条<br>2025-06-16 → 73 条<br>2024-09-30 → 693 条 | **「每月主题」** |
| 龙虎榜（个股 + 全市场） | 东财 datacenter 按 `TRADE_DATE` 可查历史 | 游资/机构行为 |
| 融资融券 | 日频历史可得 | 杠杆情绪 |
| 股东户数 | 季度历史可得 | 筹码集中度 |
| 大宗交易 | 历史可得 | 大资金动向 |
| 分红送转 | 历史可得 | 股息率 / 价值 |
| 个股资金流 | 滚动 **120 日**上限（实测可取满 120 条） | 主力行为（**只能短窗口**） |
| 公告（巨潮） | 全文检索有历史 | **风控闸门**（不是新闻） |

> **2024-09-30 拿到 693 条**（远高于常态 50–80 条）——那天是 **924 行情后的普涨/涨停潮**，
> 数量级合理。但**落地时要抽样核对**：确认它是完整历史，而不是只有极端行情才落库。

⇒ **「每月主题」不需要"从今天开始归档"，可以直接回补。** 这让阶段 0 的工作量大幅下降。

### T2 —— 只有当日快照，必须自建归档 ⏳

| 数据 | 状态 | 影响 |
| --- | --- | --- |
| 行业板块排名 + 板块资金流 | **仅当日**（`push2 clist`，无历史参数） | 板块轮动**短期不可回测** |
| 个股分钟级资金流 | 仅当日 | 盘中行为不可回测 |
| 北向分钟流向 | 上游 2024-08 起断供，只能本地自缓存 | 历史越跑越丰富 |
| 涨停 / 连板梯队 | 无现成接口，需自建 | 情绪周期不可回测 |

⚠️ **这一层是"从今天开始才有"**。每天不落盘，就永远缺这一天。**归档任务必须在建模型之前上线。**

> 补充：板块**指数日线**理论上可从东财 `push2his` 取（`secid=90.BKxxxx`）做长历史回测，
> 但本轮高频探测下该端点持续 `RemoteDisconnected`（详见 §六 风控实测），
> **未在本轮确认可用**。稳妥方案：用**板块成分股等权合成**指数——完全自控、可复现、无风控。

### T3 —— 不可回测，永不进权重 ⛔

| 数据 | 原因 | 允许的用途 |
| --- | --- | --- |
| 新闻文本 | 无历史时点快照；财联社接口已下线 | 解释层 / 风控闸门 |
| 研报与一致预期 | 有列表，但无"当时市场怎么想"的时点快照 | 解释层 |
| 社媒情绪 | 无历史 | 解释层 |

## 三、核心方法论：「预期兑现」用状态机建模，不用 NLP

这是回答「A 股受消息影响非常大怎么办」的关键。

**不读新闻，读盘面阶段。** 题材的生命周期，**每一阶段都有可观测的数量特征**：

| 阶段 | 可观测特征（全部是数据，不是文本） |
| --- | --- |
| **启动** | 题材 tag 首次出现；龙头首板；板块成交占比抬升 |
| **发酵** | tag 出现**次数上升**；板块内涨停家数增加；资金净流入转正 |
| **高潮** | tag 出现**次数峰值**；换手率极值；龙虎榜游资席位聚集 |
| **兑现 / 退潮** | 涨停**开板率上升**；龙头炸板；板块资金**净流出**；tag 消失 |

**「预期兑现」= 从高潮到退潮的相位转移。** 用**成交 / 涨停 / 资金**三个维度就能定义，
**一个中文字都不用读**。

⇒ 消息的影响被**完全投影到可测数据上**，绕开了"消息源不可靠"和"无法回测"两个死结。

## 四、系统架构

```
recommend/
├── archive/                 # 归档层 —— 地基，最先做
│   ├── backfill.py          # 一次性回补 T1（题材归因 / 龙虎榜 / 两融 / 公告）
│   ├── snapshot.py          # 每日 15:30 后落盘 T2（板块排名 / 北向 / 涨停）
│   └── store.py             # duckdb；复用 quant 项目 storage.py 的模式
│
├── factors/                 # 因子层 —— 全确定性、可解释
│   ├── price.py             # 价格 / 924以来 / 年内 / 位置分位 / 距52周高点
│   ├── momentum.py          # 相对强弱 / 突破形态 / 量价趋势
│   ├── theme.py             # 题材：tag 频次 / 首次出现 / 板块成交占比 / 生命周期阶段
│   ├── capital.py           # 资金：主力净流入 / 龙虎榜 / 两融 / 股东户数
│   └── risk.py              # 风控闸门：ST / 立案 / 减持 / 解禁 / 问询（来自公告）
│
├── screen/                  # 筛选层
│   ├── spec.py              # 筛选条件的数据结构（可序列化、可审计、白名单）
│   └── translate.py         # LLM：自然语言 → spec ★ 全系统唯一用 LLM 的地方
│
├── rank/                    # 排序层 —— 透明加权，不用 ML
└── report/                  # 输出：清单 + 因子贡献 + 风控提示 + 数据时点
```

### 四条硬设计约束

1. **LLM 只能在 `translate.py`。**
   输入「找刚启动的算力股」→ 输出
   `{"theme_tags": ["算力"], "close_position_20": [0.7, 1.0], "volume_trend_20": ">1.5"}`。
   **LLM 不参与选股、不参与排序、不产生新字段。**

2. **`spec.py` 必须是白名单枚举。** LLM 若返回未知字段 → **报错而非猜测**。这样 LLM 的幻觉**无法进入结果**。

3. **排序不用 ML。** 推荐场景样本量只有几十~几百，ML 必然过拟合。用**透明加权**：
   每个因子权重可读、可调、可审计，且**推荐理由能逐项列出**。

4. **每条推荐必须带"为什么"**：因子贡献明细 + 风控提示 + **数据时点**（避免拿陈旧数据当今天）。

## 五、系统边界（必须写死）

1. **推荐的结果不可反哺量化模型。** T3 类输入若进了量化权重，会破坏量化的可证伪性。
2. **T2 在建档完成前只能"前进"，不能"回测"。** 不要在 T2 数据上做任何"历史表现"结论。
3. **「低位」只做筛选条件，不做排序加分。** 低位可能是价值，也可能是价值陷阱；
   让它**缩小范围**，但别让它**决定买谁**。
4. 复用集合 = **归档 / 存储 / 数据同步脚本**。不复用集合 = **模型 / 回测 / 因子库**。

## 六、工程实测与坑（本轮验证）

| 项 | 实测结论 |
| --- | --- |
| 主 venv 依赖 | ❌ **没有 `requests`、没有 `mootdx`**；✅ 有 pandas / duckdb / numpy / lightgbm / pytest |
| 东财风控 | 高频探测触发 `RemoteDisconnected`。**同一秒内** `fflow/daykline` 成功而 `kline/get`、`clist` 失败 ⇒ **不是单纯 IP 封，是端点 + 频率共同触发**。必须**串行 + 间隔 ≥1s + 会话复用** |
| 行情源选择 | **优先 mootdx / 腾讯（不封 IP）**；东财**只用于其独有的数据中心接口**（龙虎榜/两融/资金流/板块排名） |
| 批量调用 | **绝不在循环里裸调东财**。每只股票之间必须 sleep |
| 板块指数 | 本机未能确认东财板块指数日线可用 ⇒ **改用成分股等权合成** |

## 七、分阶段落地建议

### 阶段 0 — 归档地基（最先做，其余都依赖它）
- 回补 T1：题材归因、龙虎榜、两融、公告
- 建立每日 T2 落盘任务（15:30 后）
- **验收**：能查询「2025-06-16 的题材热度 TOP10」

### 阶段 1 — 确定性筛选器（无 LLM）
- 实现 T0 + T1 因子：价格 / 涨幅 / 位置分位 / 题材 / 资金
- 条件先用 YAML/JSON 手写跑通
- **验收**：给定条件能出候选表 + 每个标的的因子明细

### 阶段 2 — LLM 翻译层
- `translate.py`：自然语言 → spec，白名单约束
- **验收**：说「找还在低位、近期有量、属于算力的股」能产出合理 spec

### 阶段 3 — 生命周期状态机
- 题材阶段识别（启动 / 发酵 / 高潮 / 退潮）
- **验收**：能标注某题材当前所处阶段

### 阶段 4 — 有限度回测
- **只能**回测 T0 + T1 因子（T2/T3 结构上不可回测）
- 目标**不是**验证 alpha，而是**检查筛选器会不会选出明显垃圾**（ST、退市风险、纯庄股）

## 八、诚实的边界

1. **这套系统的价值不在"预测准确率"**，而在**结构化 + 可解释 + 不漏风控**。
   用一句话说：把「翻 5,000 只股票」变成「看 20 只候选 + 每只的理由」。
2. **T3 永不进权重**是**可证伪性**要求，不是数据质量问题。
3. **推荐 ≠ 量化**。两套系统的结论**不可互相引用**。
4. 本方案**尚未验证收益**，也**不承诺收益**。任何"推荐效果"结论都必须能追溯到可回测的因子。
